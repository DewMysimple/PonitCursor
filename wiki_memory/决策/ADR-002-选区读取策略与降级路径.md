# ADR-002｜选区读取策略与降级路径

## 状态

`superseded`，由 [[决策/ADR-006-手势范围快照与后台来源读取|ADR-006 手势范围快照与后台来源读取]] 替代。

## 背景

不同 Windows 软件对选中文字的辅助功能暴露方式不同。Obsidian 基于 Electron，外层窗口可能没有正文的 UIA `TextPattern`，但渲染窗口可以提供 IA2 文本接口。

## 决策

读取辅助进程按以下顺序工作：检查前台窗口归属、自身窗口和密码控件；优先调用 UI Automation `TextPattern.GetSelection`；失败时定位 Electron `Chrome_RenderWidgetHostHWND`，通过 MSAA/IAccessible2 文本选区读取；Ctrl+C 只作为用户明确触发的补充路径。

## 理由

- UIA 是 Windows 标准接口，适用于 RichTextBox 和多数现代控件。
- IA2 降级路径覆盖 Obsidian 三种笔记模式，并保持只读，不注入脚本、不修改笔记。
- Ctrl+C 能覆盖接口不可读的应用，同时通过剪贴板序列号、窗口归属和控件安全检查避免误读旧内容或密码内容。

## 影响

- 正面影响：Obsidian 实时预览、源码和阅读视图均可使用；兼容性失败时用户仍有明确的手动补救。
- 代价或风险：特殊插件视图、PDF、图片、管理员窗口和不提供辅助信息的程序仍可能无法自动取词；跨格式或多词选区保守跳过。

## 验证方式

使用 `tests/obsidian_live_qa.py` 在独立 Obsidian 测试库验证三种模式的双击、拖选和 Ctrl+C；使用 `tests/browser_qa.py` 和 `tests/desktop_qa.py` 检查网页、RichTextBox、多词过滤、密码控件和剪贴板保持。
