# ADR-003｜变更提交与远程推送

## 状态

`active`

## 背景

用户要求工程后续每一次完整对话产生的修改都可追溯，并由远程仓库统一管理。

## 决策

PointCursor 使用 Git 管理，远程仓库固定为 `https://github.com/DewMysimple/PonitCursor.git`。每次完整对话完成修改并通过必要验证后，创建一次提交并立即执行 `git push`；推送失败则保留本地提交并在日志记录失败原因。

## 理由

- 一次对话对应一个可审查变更集，便于回滚和定位行为变化。
- 远程推送提供异地备份和跨设备协作入口。
- 将规则写入根目录 `AGENTS.md`、当前约束和本 ADR，后续 Agent 启动即可读取。

## 影响

- 正面影响：代码、文档和工程记忆保持同步，远程仓库可直接审查。
- 代价或风险：每轮工作都需要完成验证和推送；网络或凭据故障会让本地提交暂时领先远程。

## 验证方式

检查 `git status --short --branch`、`git log -1 --oneline` 和 `git ls-remote origin HEAD`，确认工作区干净且远程 HEAD 与本地提交一致。
