# ADR-005｜完整手势提交与显式重复播报

## 状态

`superseded`，由 [[决策/ADR-006-手势范围快照与后台来源读取|ADR-006 手势范围快照与后台来源读取]] 替代。

## 背景

旧实现把普通鼠标、键盘和窗口状态变化都当作失效事件：它们会取消已完成划词的读取并停止正在播放的语音。鼠标松开后还固定等待 250 毫秒，放大了有效选区被后续操作撤销的时间窗口。Ctrl+C 又沿用当前选择的发音票据，因此同一选区自动读过或复制读过后，再次明确复制会被去重。

## 决策

- 输入钩子只向主进程投递完整的拖选释放、双击释放和用户明确按下的 Ctrl+C；普通单击、按键、右键、滚轮、光标和窗口状态变化不生成取消／停止事件。
- 完整划词手势提交后等待约 50 毫秒，让目标控件处理低级鼠标松开消息，然后立即读取选区。
- 只有新的完整划词手势或 Ctrl+C 才替代仍在执行的旧读取；已经取得的合法单词不因后续普通输入或窗口变化被主进程丢弃，已经开始的播放也不因此停止。
- 每次 Ctrl+C 建立新的请求代次。即使文本和选区都未变化，也允许再次播报；快速重按取消旧剪贴板读取时必须释放串行读取状态。

## 理由

用户意图在完整划词或明确复制时已经成立。把无关输入当作撤销信号既没有安全收益，又会降低成功率、截断短词并放大 UI 消息调度抖动。安全边界继续由读取时的前台窗口、进程归属、密码控件检查、剪贴板序列号和单词规则保证。

## 影响

- 正面影响：Zira 路径更快开始取词；普通光标和窗口操作不再干扰已提交请求；同一单词可连续 Ctrl+C 重听。
- 取舍：若用户在约 50 毫秒内主动清除选区或切换前台窗口，辅助进程仍会按安全规则返回过期／不可用；程序不会读取后台窗口。
- 新的合法单词仍可替换尚未完成的旧语音请求，以避免形成延迟队列。

## 验证方式

- 自动测试检查每次显式复制都有新票据、Zira 对同一单词的新请求会再次开始播放。
- RichTextBox 桌面测试在双击松开后立即发送 Esc，验证选区请求不被普通输入撤销。
- WASAPI loopback 对 Zira 首次与重复播放做完整波形及词头相关性检查。
