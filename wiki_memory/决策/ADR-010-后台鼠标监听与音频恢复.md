# ADR-010｜后台鼠标监听与音频恢复

## 背景

用户反馈 Obsidian 闲置超过五分钟后自动划词失效，但手动试听正常。独立输入线程可以避开 UI 卡顿，却不能保证低级鼠标钩子永不超时；Windows 静默移除钩子后，旧实现没有恢复入口。受控线程卡顿对照复现了旧钩子停止收到后续鼠标事件。

## 决策

- `InputMonitor` 在原有专用 STA 线程创建消息窗口，通过 `RIDEV_INPUTSINK` 接收后台 Raw Input 鼠标事件，删除低级鼠标钩子。继续复用纯 `SelectionGesture`，不并行维护第二套手势识别或重复事件去重链路。
- 使用消息的坐标和时间，不用 UI 处理时的当前鼠标位置计算手势。处理按下事件时锁定来源窗口。超过 500ms 的积压包清空手势状态并丢弃，以免休眠或卡顿恢复后把旧坐标误用于另一窗口；首次新手势正常处理。
- Ctrl+C 需要在目标应用复制前捕获剪贴板序列号，因此保留轻量键盘钩子，每 30 秒重新注册；先取得新钩子再释放旧钩子，不改写剪贴板、不拦截正常复制。
- Obsidian/Chromium 焦点保护区分 `safe`、`blocked`、`unavailable`。辅助功能临时异常继续保守跳过本次读取，但可以进入原有有限重试；确认密码的 `blocked` 不重试或绕过。Reader 总时限仍约 900ms。
- WASAPI 使用 `IAudioClock` 检查播放进度，750ms 无推进时重开设备；每个新发音请求提交采样前确认默认设备。PCM 直到设备时钟确认播放完毕才释放，未完成请求重开后从零播放，完成或取消的旧词不重播。
- 保留原有系统语音合成后端、配置、单实例、选词安全规则和模块边界。故障注入入口与来源 PID 限制仅存在于 QA 构建。

## 验证与限制

输入线程卡顿、桌面连续双击、Obsidian 闲置后的首次手势、浏览器密码保护和实际音频回录分别验证。具体通过范围和时延见来源日志及 `COMPATIBILITY.md`，不能将短期测试外推为所有插件、设备或多小时场景均已验证。

参考：[Raw Input](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-raw-input)、[低级鼠标钩子超时](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc)。本决策更新 [[决策/ADR-008-固定Zira与独立输入线程]] 的输入实现；[[决策/ADR-006-手势范围快照与后台来源读取]] 的来源范围和安全原则仍有效，语音范围继续遵循 [[决策/ADR-009-限定美式与英式系统语音]]。
