# 当前约束

> 记录 Agent 修改项目时必须遵守的限制。没有依据的内容不要写入。

## 技术约束

- 主程序使用 C#、.NET Framework 4.8 和 WinForms；构建依赖 Windows 自带编译器与系统程序集，不下载 NuGet 或 npm 包。
- 发音可使用本机安装的英文系统语音或随包发布的 Kokoro-82M int8 ONNX 后端；运行时不访问网络、不需要账号、API 密钥、全局 Python/Node.js 或管理员权限。
- Kokoro 二进制、模型和声线由 Git LFS 管理，发布时必须完整复制 `third_party/kokoro-runtime` 并保留第三方许可证。

## 兼容性约束

- 重点保证 Obsidian 1.13.7 的实时预览、源码模式和阅读视图；其他软件取决于其 UIA/MSAA/IA2 暴露能力。
- 只接受单个英文词，允许 `don't`、`well-known` 等内部撇号或连字符；中文、数字、网址、多词、密码控件、扫描图片和 PDF 不触发。
- 读取必须有边界：鼠标松开后约 50 毫秒等待选区、辅助读取约 900 毫秒超时；只有新的完整划词手势或明确 Ctrl+C 才替代旧读取，普通输入不得取消已完成的手势或正在播放的读音。
- Kokoro 推理不能阻塞托盘 UI；生成在独立工作进程中执行，新请求必须停止旧音频，并能终止尚未完成的旧推理。

## 质量约束

- 变更完成后必须执行与范围匹配的测试、`git diff --check` 和记忆体检；可运行源码修改必须形成 Git 提交并推送远程仓库。
- 不提交用户设置、笔记、浏览器缓存、账号信息、令牌或生成目录；文档使用中文，命令和 API 名称保留原文。

## 操作边界

- 不主动模拟 Ctrl+C，不恢复或改写剪贴板，不保存选中文字、阅读历史或按键记录。
- 不修改 Obsidian 启动参数、笔记内容或用户配置；集成测试必须使用独立测试库和浏览器配置。
- 后续每一次完整对话造成的修改，在验证完成后都要提交 Git 并执行 `git push`；失败时记录原因，不声称已推送。
