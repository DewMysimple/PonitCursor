# 系统架构

> 只记录当前有效的模块关系、数据流、运行方式和关键技术边界。

## 架构概览

PointCursor 是一个无窗口驻留的 WinForms 托盘应用。主进程在用户会话中安装低级鼠标、键盘钩子和剪贴板格式监听器；钩子只投递完整选择手势和明确 Ctrl+C，不为普通输入制造取消消息。选区读取由独立的 `PointCursor.Reader.exe` 完成，以便第三方辅助功能接口卡住时可以在约 900 毫秒后终止，不阻塞托盘 UI。读取结果经过单词规则和请求代次门控后交给所选语音后端：Windows 语音由后台 `System.Speech.Synthesis` 合成为 PCM，Kokoro 由独立 Node.js 工作进程完成音素转换和 ONNX 推理；两者共用保持就绪的 WASAPI 输出通道。

## 数据流或请求流

1. 拖动释放或双击释放后记录当时的前台来源窗口、按下／释放坐标和剪贴板序列号；普通按键、单击、右键和滚轮不向主进程发送取消事件。
2. 主进程约 10 毫秒后调用读取辅助进程。自动划词请求以已记录的来源窗口为边界，不要求它在读取时仍处于前台；读取器可从后台来源 HWND 定位原控件，优先读取仍存在的 UIA／IA2 选区，选区被后续点击清空时按两个手势端点重建文本范围。Obsidian 在此期间插入 `==` 高亮标记时，读取器会核对原手势片段、当前同行标记和辅助功能包围词，恢复被端点偏移截短的原单词，而不会从多词范围裁出一个词。密码控件、跨进程命中和无效窗口仍保守拒绝；Ctrl+C 的安全检查仍要求原窗口保持前台。
3. 读取结果限制为单个英文词（可含内部撇号或连字符）；不合规则丢弃。只有新的完整选择手势或 Ctrl+C 才替代仍在读取的旧请求；划词完成后的窗口切换、光标移动、普通点击和按键不会丢弃结果或停止播放。
4. 选词成功后由所选英文语音异步播放。Windows 后端在后台合成为 PCM；Kokoro 启动时预热并复用模型，生成 24 kHz PCM16 WAV，读入后立即删除。两者共用 WASAPI 输出。新词使旧音频失效，只保留最新待处理请求；普通旧推理完成后丢弃结果，取消后仍卡住约 1 秒才终止进程。
5. Ctrl+C 仅在检测到用户真实按键、且窗口产生新的剪贴板序列号后读取短文本；不主动复制、不改写剪贴板，并再次确认控件状态。每次按键获得新票据，同一选区和同一单词可以重复播报。

## 运行与部署

双击 `dist/PointCursor/PointCursor.exe` 后，主进程和同目录读取辅助进程一起运行；启动、恢复或选择 Kokoro 时后台预热并启动 `Kokoro/node.exe worker.mjs`。设置存于当前用户 `%LOCALAPPDATA%\PointCursor\settings.xml`。构建不需要 NuGet、npm 或网络，使用 Windows 自带 .NET Framework 4.8 C# 编译器并复制已纳入源码的 Git LFS 资产。退出时卸载钩子、剪贴板监听器、辅助进程、Kokoro 工作进程、临时 WAV 和语音资源。
