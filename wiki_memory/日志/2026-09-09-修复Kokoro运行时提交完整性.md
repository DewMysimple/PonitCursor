# 2026-09-09｜修复 Kokoro 运行时提交完整性

- 时间：2026-09-09（北京时间）
- 类型：`fix`
- 状态：`完成`
- 目标：解决其他开发环境克隆仓库后 Kokoro 工作进程缺少 `transformers.node.mjs`、导致 `ERR_MODULE_NOT_FOUND` 和发音失败的问题。

## 根因

- 根目录 `.gitignore` 的 `dist/` 是未锚定规则，会忽略 `third_party/kokoro-runtime/node_modules/` 下所有依赖包的编译 `dist/` 目录。
- 本机残留的安装文件使本机测试和打包正常，但远程 Git 提交只包含依赖包的 `package.json` 与许可证，没有其 `dist` 编译产物。
- Transformers.js 的 Node 导出指向 `./dist/transformers.node.mjs`；因此干净克隆启动工作进程时出现 `ERR_MODULE_NOT_FOUND`。ONNX Runtime 和 phonemizer 的编译目录也同时受影响。

## 修复

- 将忽略规则收紧为仅忽略仓库根目录 `/build/` 和 `/dist/`。
- 将 Kokoro 运行时依赖包内部的 185 个编译文件纳入版本控制。
- 扩展 `build.ps1` 与 `KokoroSpeechEngine.Available` 的关键入口检查，避免不完整运行时被误判为可用。
- 更新 README、构建发布知识和部署排障说明，明确源码克隆需要 Git LFS，并保留完整运行时目录。

## 验证

- `build.ps1 -Test -Package` 通过：64 项自动检查、C# 桥接合成、工作进程取消/复用、直接 Node 冒烟和 ZIP 打包均通过。
- 本机运行时的 4 个依赖包 `dist` 目录共 185 个文件已可被 Git 追踪；下一步提交并推送后用干净克隆复验。
