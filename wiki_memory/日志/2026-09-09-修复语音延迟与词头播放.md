# 2026-09-09｜修复语音延迟与词头播放

- 目标：处理跨开发环境的语音加载迟缓、首次播报词头缺失，以及运行时维护问题。
- 用户确认：Kokoro 与 Windows 语音均出现过词头缺失。
- 日志索引：[[日志/MOC_工作日志|工作日志 MOC]]。

## 检查与采用的修复

- 确认旧 Kokoro 首次发音才加载模型；鼠标取消正在合成的请求会杀掉工作进程，使后续反复冷启动。
- Kokoro 改为启动／恢复／选择语音时后台静默预热，显式限制最多 4 个 ONNX 推理线程。单个工作线程仅保留最新待处理词，普通旧推理完成后丢弃，取消后卡住约 1 秒才终止；启动上限 15 秒、有效推理上限 10 秒。
- 两个后端都合成为完整 PCM16、24 kHz、单声道，交给持续就绪的 WASAPI 输出。设备打开先提交 150 毫秒静音，普通词不额外填充；保留每个源采样，不裁剪弱辅音。
- 修正播放状态回调的代次校验，避免旧回调覆盖新词。退出清理线程、设备、子进程和临时 WAV；父进程输入关闭时 Node 在预热期间也能退出。
- 增加运行时清单、启动长度检查、构建 SHA-256 校验、离线诊断脚本和按清单同步发布目录。固定运行时文本 LF，避免换机换行转换破坏哈希；保留原有第三方许可证和 LFS 资产。
- 测试版设置使用独立编译配置，避免桌面回归触及用户设置。

## 验证

- 87 项自动检查通过，含 PCM 极弱首采样、跨缓冲尾部、取消、SAPI 输出、Kokoro 预热和连续换词、卡死恢复、临时目录清理、缺失／损坏／LFS 指针检查。
- 本机完整 Kokoro 预热就绪约 1.0～2.4 秒，提前后台完成；预热后 hello 请求到输出开始约 0.65 秒，连续取消后最新词约 0.56～0.64 秒；Windows 约 3～12 毫秒。不含选区读取或物理设备声学时延。
- 10 次连续换词和取消保留同一 Node PID；模拟卡死取消后约 1.0～1.1 秒终止，并成功重启。预热期间关闭父输入后约 116 毫秒退出。
- Windows 默认输出 loopback：Zira、Kokoro af_heart、bf_emma 各两次播放，整词与词头 100 毫秒相关性均超过 0.9998。首次回录被其他软件声音干扰，用户暂停其他声音后重测通过；不把受干扰录音作为证据。
- 出站阻止范围覆盖测试主程序、读取器、测试程序和 Kokoro Node。83 项当时的自动检查及桌面双击、拖选、重复选词、暂停恢复、密码保护、退出通过。剪贴板无法完整快照，复制交互检查按保护规则跳过；没有切断整机网络。
- 从 Git 暂存内容重新检出到忽略目录，290 个文件哈希、Windows/Kokoro 诊断合成及独立构建通过，验证换行与 LFS 还原后的可构建性。
- 发布目录与 ZIP 已更新。本机新版以托盘模式启动，预加载 Emma；用户设置 SHA-256 与更新前一致。测试防火墙规则已清理。
