# 2026-09-11｜提升 Zira 划词稳定性与响应速度

- 目标：只以 Microsoft Zira Desktop 作为本轮验收语音，提高划词成功率，防止普通光标／窗口／输入变化撤销请求或截断读音，允许同一单词重复 Ctrl+C 发音，并降低鼠标松开到开始取词的等待。
- 日志索引：[[日志/MOC_工作日志|工作日志 MOC]]。

## 根因与修改

- 旧输入钩子在左键按下、普通按键、右键和滚轮时发送 `reset`，主进程收到后同时取消选区读取并停止语音。已完成划词在 250 毫秒等待期间很容易被下一次输入撤销，已经开始的短词也可能被截断。
- 输入钩子现在只投递完整拖选、双击和 Ctrl+C；普通输入只维护钩子内部状态，不再触碰读取或播放。新的完整选择手势／复制仍会替代旧读取，暂停、设置变更和退出仍会显式停止语音。
- 选区稳定等待由 250 毫秒缩短为 50 毫秒。辅助进程仍保留前台窗口、进程归属、密码控件和约 900 毫秒超时边界；一旦辅助进程返回合法单词，主进程不再用稍后的前台窗口状态二次丢弃它。
- 每次 Ctrl+C 都递增选择代次并获得独立发音票据，解决自动发音或首次复制后同词无法重读的问题。
- 快速连续 Ctrl+C 取消上一轮异步剪贴板读取时，现在无条件释放 `copying` 串行标志，使已重新武装的定时器可以处理最新复制，避免状态永久卡住。

## 验证

- `build.ps1 -Test -OutputDirectory build\goal-zira`：修改中间版本 88 项通过；补充 Zira 同词重复请求后最终完整结果以本次提交前验证为准。
- RichTextBox 桌面链路：双击松开后立即发送 Esc 仍播报 `hello`；拖选、重新选择、暂停恢复、密码保护和退出通过。从第一次鼠标按下到 `已发音` 状态约 373 毫秒，包含双击动作约 0.2 秒。
- 当前系统剪贴板包含测试脚本无法无损快照的格式，因此桌面 Ctrl+C 写入交互按保护规则跳过；没有覆盖用户剪贴板。重复复制由请求票据自动检查及 Zira 同词重复请求覆盖。
- Zira WASAPI loopback：首次受系统其他声音干扰未达严格阈值，安静重试通过。首次／重复整词相关性为 0.999955／0.988853，词头 100 毫秒相关性为 0.999994／0.985327，确认软件输出未截断。

## 边界

- 本轮不为 Kokoro 调整行为或性能；既有自动回归仍运行，避免通用输入编排改动造成退化。
- 若用户在约 50 毫秒内主动清空选区或把原窗口切到后台，读取仍按安全边界失败；不会为了成功率读取后台窗口。
- 软件回录不能代替真实音箱／耳机试听，实际 Obsidian 环境仍需用户反馈。
