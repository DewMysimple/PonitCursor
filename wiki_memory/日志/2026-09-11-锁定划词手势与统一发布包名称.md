# 2026-09-11｜锁定划词手势与统一发布包名称

- 目标：解决完成划词后立即切换窗口或点击别处导致 Microsoft Zira Desktop 无反应的问题，并把后续便携包统一命名为 `PointCursor.zip`，解压后直接得到 `PointCursor` 软件目录。
- 日志索引：[[日志/MOC_工作日志|工作日志 MOC]]。

## 根因

- 上一轮虽已删除普通输入产生的取消消息，但主程序在处理手势和启动读取时仍检查“来源窗口现在是否前台”，读取辅助进程在开始、返回和 IA2 路径也重复检查前台状态；切窗会把已完成手势判为过期。
- 输入钩子只保存鼠标释放点并延迟约 50 毫秒。用户在此期间点击别处时，目标控件会清空真实选区，读取器没有足够信息恢复原来的词。

## 修改

- 输入通知现在同时保存鼠标按下和释放坐标；主程序使用七字段协议把来源 HWND 与两个端点交给独立读取进程，读取等待缩短到约 10 毫秒。
- 自动划词不再依赖读取时的全局前台窗口。UIA 路径可从已记录来源 HWND 的原生子窗口和有限辅助功能树重新定位控件；Electron IA2 路径可直接定位来源渲染窗口。真实选区已被清空时，分别通过 `TextPattern.RangeFromPoint` 或 IA2 `offsetAtPoint` 重建手势范围。
- 后台来源读取只接受鼠标手势记录的窗口和坐标；进程归属、密码控件、单词过滤及约 900 毫秒超时不变。Ctrl+C 仍保留严格前台和剪贴板来源检查。
- QA 构建使用独立单实例互斥，执行桌面回归不再要求关闭正在运行的正式版。
- 发布脚本生成 `dist/PointCursor.zip` 并移除旧命名的 `dist/PointCursor-Windows-x64.zip`；ZIP 顶层保持 `PointCursor/` 软件目录。

## 验证

- 完整自动测试：89 项通过，包括 Microsoft Zira Desktop 实际合成与同词重复请求。
- RichTextBox + Zira 桌面端到端回归连续 3 轮通过：拖选释放后无额外测试等待立即切换前台窗口，仍播报 `hello`；拖选释放后立即点击 `world` 位置，仍播报原来的 `hello`。
- 直接读取证据：后续单击使 RichEdit 选区变为折叠范围后，七字段 `gesture` 请求仍返回 `word|hello`，确认不是依赖尚未清空的残留选区。
- 拖选、重复选择、同词重复 Ctrl+C、暂停、密码框拒绝、剪贴板不改写和退出清理同时通过。
- Chrome 本地合成页面验证真实选区和切换到另一窗口后的后台来源读取均返回 `hello`，多词被忽略，密码框在前台及切窗后都被阻止。
- 隔离 Obsidian 1.13.7 测试库的实时预览、源码和阅读视图全部通过：单词、连字符、撇号、拒绝多词／跨段／空选区，以及三种视图的真实双击、拖选和 Ctrl+C；合成笔记哈希保持不变。
- `dist/PointCursor.zip` 大小为 131,339,366 字节，SHA-256 为 `02EF00213A7DDBCEA1544DA16B18E608F3BC3A8C276C1E26173A80565F637DB3`；归档条目统一位于 `PointCursor/` 顶层，旧命名 ZIP 已移除。
