# 重复启动直接唤醒设置窗口

## 请求与范围

用户要求后台驻留时再次打开软件直接聚焦，不再弹出“已在运行”提示；同时询问类似 Zira 的其他语音。实现单实例唤醒并说明语音选项，产品当前仍固定 Zira，没有安装语音或恢复多后端配置。

## 实现

- 复用 App 内的消息窗口，按现有互斥名称区分当前用户、Windows 会话和正式/QA 实例；托盘初始化结束才公布接收窗口。
- 第二个进程最多等待接收窗口约 3 秒，授予前台权限，以 1 秒超时消息请求恢复设置，使用返回且核对进程归属的 HWND 完成聚焦后退出。没有新增依赖、后台线程或轮询服务。
- 显示设置时恢复最小化，显式 ShowWindow 避免静默启动继承隐藏窗口样式；沿用现有设置窗体。获取互斥改为实际 WaitOne，处理旧实例退出及 abandoned mutex。
- 删除重复实例提示。取词、音频、系统语音、用户设置与笔记均未修改。

## 验证

- `build.ps1 -Test -OutputDirectory build/candidate`：98 项自动检查通过。
- 新增 `single_instance_qa.py` 和 Fixture 启动入口，由真正的前台测试进程创建第二个实例，覆盖静默驻留唤出、隐藏恢复、最小化恢复、被遮挡时聚焦、连续五次重复启动、正常退出及两个进程同时冷启动。
- 验证检查实际 GetForegroundWindow，而不只检查窗口可见；检查第二个进程正常退出，避免遗漏模态提示。连续启动后只保留一个可见设置窗口。
- 调试时发现测试辅助函数发送 Alt 后可能留在菜单状态，导致 Windows 拒绝前台切换；测试先退出该状态再启动。隐藏/显示可能重建 HWND，测试不把 HWND 永久不变当成产品要求。
- 测试只使用 QA 配置与合成窗口，不读写剪贴板、不改笔记。正式版和 QA 互斥继续隔离。

## 语音咨询

同类候选包括 Windows 的 David/Hazel、支持 Windows SAPI 5 的开源 RHVoice、商业 CereProc Windows 语音。讲述人自然语音是否能被 System.Speech 枚举需要另行验证，不能只凭 Windows 设置中可见就视为本程序可用。此次仅提供选项，没有采用新的语音架构决策。

参考：[Microsoft 语音列表](https://support.microsoft.com/en-us/accessibility/windows/narrator/appendix-a-supported-languages-and-voices)、[RHVoice](https://github.com/RHVoice/RHVoice)、[CereProc FAQ](https://app.cereproc.com/faqs/)、[前台权限说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-allowsetforegroundwindow)。

## 交付与限制

更新本机程序及便携包，按仓库约定同步文档、刷新记忆索引并提交推送。窗口唤醒遵守 Windows 前台权限规则；后台 UI 卡死时第二个进程有界退出，不弹旧提示或无限等待。管理员权限与普通权限之间启动等额外场景未专门测试。

## 待确认长期记忆

无。直接唤醒是本轮明确要求，语音咨询未视为重新启用多语音的授权。
