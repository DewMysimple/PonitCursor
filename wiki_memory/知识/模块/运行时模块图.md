# 运行时模块图

## 一句话结论

运行时由托盘主进程、选区读取辅助进程和系统语音三部分组成，`Core` 中的规则和门控把输入事件变成一次安全、可取消的播报。

## 适用范围

修改全局输入、选区读取、语音、设置或托盘生命周期时使用；文件入口和关系以 `src/` 当前实现为准。

## 详细内容

| 模块 | 入口与职责 | 关键边界 |
| --- | --- | --- |
| 托盘应用 | `src/App.cs` 的 `TrayApp` / `MessageWindow` | UI 线程只编排事件和状态，不直接执行可能卡住的选区接口 |
| 输入监听 | `src/InputMonitor.cs` | 低级钩子只识别鼠标释放、双击、拖动、Ctrl+C 和重置事件 |
| 读取客户端 | `src/SelectionClient.cs` | 每次请求带窗口、坐标、代次；900ms 无响应就杀掉辅助进程 |
| 读取辅助进程 | `src/SelectionReader.cs`、`src/LegacySelection.cs` | UIA 优先，Electron 使用 IA2；保护自身窗口、密码控件和跨进程边界 |
| 规则与门控 | `src/Core.cs` | 单词最多 64 字符；只允许英文字母及内部撇号/连字符；同一代只接受一次 |
| 语音 | `src/SpeechService.cs` | 仅系统英文语音；新词取消旧语音；异步播放 |
| 设置界面 | `src/SettingsForm.cs`、`AppSettings` | 只持久化语音、语速、音量和复制开关 |

## 常见问题或陷阱

- 修改读取接口时要保持独立进程边界，否则某个应用的 COM/辅助功能调用可能卡住托盘。
- 选区结果不能直接等同于可播报文本，必须经过 `WordRules.Normalize` 和请求代次检查。
- Electron 外层窗口的 UIA 结果可能只是包装层；Obsidian 兼容需要定位正文渲染窗口。
