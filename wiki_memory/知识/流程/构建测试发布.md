# 构建、测试与发布

## 一句话结论

使用 Windows PowerShell 执行 `build.ps1`，由系统 .NET Framework 4.8 编译器生成可运行目录，并复制已检出的 Kokoro Git LFS 资产；`-Test` 验证规则、取词客户端和 Kokoro 实际合成，`-Package` 生成便携 ZIP。

## 适用范围

每次源码、构建脚本或发布文档变更后使用；桌面集成测试在需要真实鼠标/窗口行为时运行。

## 详细内容

1. 仅需生成发布产物时，双击仓库根目录的 `buildStart.cmd`，或从命令行执行 `buildStart.cmd`；脚本默认调用 `build.ps1 -Package`。
2. 需要同时执行完整自动测试时，运行 `buildStart.cmd -Test`，等价于执行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Test -Package`。
3. 检查 `build\tests\PointCursor.Tests.exe` 输出和退出码；自动测试会经 C# 桥接实际生成和播放美式、英式 Kokoro 单词。
4. 检查 `build\qa\kokoro-smoke.wav`；构建脚本会直接调用便携目录中的 Node.js/ONNX 工作进程，确认本地模型能生成有效 WAV。
5. 对行为改动按需运行 `python tests\desktop_qa.py`、`python tests\browser_qa.py` 和独立 Obsidian 流程；不要把用户笔记或浏览器配置放入仓库。
6. 检查 `dist\PointCursor` 和 `dist\PointCursor.zip`；ZIP 根层应直接包含主程序、读取辅助进程、核心 DLL、配置文件和完整的 `Kokoro/` 目录，不得再包含额外的 `PointCursor/` 包装目录。
7. 执行记忆体检、`git diff --check`，然后提交并推送；Kokoro 大文件必须通过 Git LFS 上传成功。

## 常见问题或陷阱

- 编译器必须来自 Windows `.NET Framework\Framework64\v4.0.30319`，缺少 `System.Speech` 或 UI Automation 程序集时构建会失败。
- `buildStart.cmd` 会把 `PSModulePath` 限定为 Windows PowerShell 自带模块目录，避免从 PowerShell 7 或集成终端启动时误加载不兼容模块；它会原样传递额外参数，并保留构建失败退出码。
- 仓库根目录 `/dist/` 和 `/build/` 被 Git 忽略；Kokoro 依赖包内部的 `dist/` 是运行时必需的 JavaScript 编译产物，必须随源码提交，不可被通用忽略规则覆盖。
- `build.ps1` 会检查 Transformers.js、ONNX Runtime、phonemizer 的关键入口文件；这样干净克隆缺少依赖时会在构建开始阶段失败，而不是运行时才显示 Kokoro 发音失败。
- `third_party/kokoro-runtime` 不是可省略缓存；缺少 LFS 对象时构建应失败，不能发布只含指针文本的模型或二进制。
- Kokoro 模型和内置 Node.js 会显著增大发布包；不要运行 `npm install` 覆盖已裁剪、已验证的便携运行时。
- Obsidian 和浏览器测试使用独立配置；终止测试进程后要确认没有留下 PointCursor 或测试浏览器进程。
