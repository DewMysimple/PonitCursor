# 构建、测试与发布

## 一句话结论

使用 Windows PowerShell 执行 `build.ps1`，由系统 .NET Framework 4.8 编译器生成可运行目录；`-Test` 验证规则和集成客户端，`-Package` 生成便携 ZIP。

## 适用范围

每次源码、构建脚本或发布文档变更后使用；桌面集成测试在需要真实鼠标/窗口行为时运行。

## 详细内容

1. 在仓库根目录执行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Test -Package`。
2. 检查 `build\tests\PointCursor.Tests.exe` 输出和退出码；当前基线为 59 项自动检查。
3. 对行为改动按需运行 `python tests\desktop_qa.py`、`python tests\browser_qa.py` 和独立 Obsidian 流程；不要把用户笔记或浏览器配置放入仓库。
4. 检查 `dist\PointCursor` 和 `dist\PointCursor-Windows-x64.zip`，保留完整目录中的主程序、读取辅助进程、核心 DLL 和配置文件。
5. 执行记忆体检、`git diff --check`，然后提交并推送。

## 常见问题或陷阱

- 编译器必须来自 Windows `.NET Framework\Framework64\v4.0.30319`，缺少 `System.Speech` 或 UI Automation 程序集时构建会失败。
- `dist/` 和 `build/` 默认被 Git 忽略；发布包是可再生物，不应把测试缓存一起提交。
- Obsidian 和浏览器测试使用独立配置；终止测试进程后要确认没有留下 PointCursor 或测试浏览器进程。
