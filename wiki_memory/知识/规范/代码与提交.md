# 代码与提交规范

## 一句话结论

PointCursor 的可维护变更必须同时更新实现、中文说明和必要的工程记忆，并在验证后以一次 Git 提交推送远程。

## 适用范围

所有后续完整对话造成的代码、测试、构建脚本、发布说明和记忆文件变更。

## 详细内容

- C# 代码保持 .NET Framework 4.8 和现有程序集边界；公共行为变化要同步 `README.md` 或 `COMPATIBILITY.md`。
- 文件按现有职责放入 `src/`、`tests/`、`wiki_memory/`；生成目录 `build/`、`dist/` 不提交。
- 单词规则、超时、取消、剪贴板保留和密码保护属于安全边界，修改时必须补充相应验证。
- 自述文件和工程记忆使用中文，Windows API、程序集、类名和命令保留准确原文。
- 每轮结束执行 `python wiki_memory/工具/memory_lint.py check`、`git diff --check`、构建/测试，再执行 `git add`、`git commit`、`git push`。
- 提交信息要说明结果，例如 `feat: 完成离线划词发音首版` 或 `docs: 更新兼容性记录`；推送失败需写入日志。

## 常见问题或陷阱

- 不要为了测试主动模拟复制，也不要读取或重写用户原有剪贴板。
- 不要把测试生成的浏览器缓存、Obsidian 测试库、设置文件和令牌提交到仓库。
- 一次对话若修改了多个相关文件，应合并为同一个可审查提交，而不是留下未提交的半成品。
