# 部署与故障排查

## 一句话结论

PointCursor 是便携式 Windows 程序，解压后保持完整目录并双击 `PointCursor.exe`；可选择内置 Kokoro 或 Windows 系统语音。遇到不发音时先检查 `Kokoro/` 目录、系统语音、音频输出和设置页状态，再用 Ctrl+C 补充取词路径。

## 适用范围

日常使用、换机部署、断网运行、语音缺失、自动取词失败和退出清理。

## 详细内容

- 首次运行会打开中文设置窗口；关闭设置后程序继续驻留托盘。双击托盘图标可再次打开。
- 默认优先沿用 Microsoft Zira Desktop（en-US）设置；设置页同时列出当前已安装的 Windows 英文语音和 28 个内置 Kokoro 英文声线，并可调整语速和音量。
- 设置写入 `%LOCALAPPDATA%\PointCursor\settings.xml`。文件损坏时程序回到默认值并提示，不会读取其他数据。
- 自动取词失败时保持单词选中并按 Ctrl+C；程序只接受新的剪贴板序列号，不修改剪贴板内容。
- 没有英文语音时在 Windows 设置中安装英语语音包后重启 PointCursor；语音包安装本身可能需要网络，但运行和发音不需要网络。
- Kokoro 在启动或选择声线后后台加载并预热；若一直停留在准备状态，先运行发布目录中的 `diagnose.ps1`，再检查 `Kokoro/node.exe`、`Kokoro/model/`、`Kokoro/voices/` 和安全软件拦截记录。切换 Windows 语音可继续使用基本发音。
- 从源码仓库换机或在其他开发环境构建时，先安装 Git LFS 并执行 `git lfs pull`；同时确认 `third_party/kokoro-runtime/node_modules/` 下的编译 `dist/` 目录存在。缺少 `transformers.node.mjs`、ONNX Runtime 或 phonemizer 入口文件会导致 Node 工作进程无法输出 `READY`。
- 退出托盘菜单后应释放鼠标/键盘钩子、剪贴板监听、读取辅助进程和语音资源；可在任务管理器确认没有残留进程。

## 常见问题或陷阱

- 程序必须与 `PointCursor.Reader.exe`、`PointCursor.Core.dll`、两个 `.config` 文件和完整的 `Kokoro/` 目录一起移动或解压。
- 管理员权限窗口可能因 UIPI 访问边界无法读取；普通用户权限启动 PointCursor 不应被要求提升。
- 自动取词支持取决于目标软件的辅助功能实现；PDF、图片和扫描文本没有 OCR 适配。

## 语音延迟与首词排查

- 启用时两种语音共用持续就绪的 WASAPI 通道；暂停释放设备。合成音频保留全部采样，设备打开时先提交 150 毫秒静音。
- 新鼠标动作只使旧请求失效，不再反复杀掉已加载 Kokoro。取消后卡住约 1 秒才终止旧进程，新的有效推理上限 10 秒、启动预热上限 15 秒。
- `diagnose.ps1` 校验全部运行时文件并静默合成固定 hello；不修改设置。缺失／长度不符时检查 LFS，哈希不符时重新完整解压或重建。运行时文本由 `.gitattributes` 固定 LF；有意更新依赖后手动刷新 `tools/runtime_manifest.py` 清单。
- 软件 loopback 通过但仍听到词头缺失时，记录设备类型、具体声线与单词，再做硬件侧复验；不要声称数字回录等同于扬声器实测。
